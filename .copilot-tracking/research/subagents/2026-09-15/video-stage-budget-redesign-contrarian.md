## Contrarian findings

### 1. Editor-local monotonic budget plus durable UTC projection

- **Supports (narrowly):** `wait_for_fanin` already measures its local deadline with injected `time.monotonic`, and its test seam supports deterministic clock testing. `podcaster/video/editor.py:245-288`; `tests/test_editor.py:186-240`.
- **Weakens:** `run_video_generation` takes `now` as a UTC wall-clock value and passes it to the UTC lease claim, but it has no injected monotonic clock or budget. `podcaster/video/job_runner.py:774-805`, `podcaster/video/job_runner.py:851-865`; `podcaster/video/editor.py:126-155`. Therefore the proposed “one editor-local monotonic budget” is not yet a cross-boundary contract.
- **Weakens materially:** a persisted UTC projection cannot preserve an editor process's monotonic epoch. A redelivered editor and separately scaled recorder receive only their own process-local monotonic clocks; recorder input is `(job_id, clip_index)`, queue dequeue count, clipset and environment. `podcaster/video/recorder.py:339-395`; `podcaster/queue.py:63-78`, `podcaster/queue.py:117-190`. Clock skew, wall-clock correction, or delayed queue delivery can cause a UTC-projected deadline to be earlier/later than the originating local monotonic deadline.
- **Unresolved:** workspace evidence defines neither an allowed skew/grace window nor an authoritative rule when local remaining time and durable UTC remaining time disagree. This must be stated before claiming cross-worker deadline safety.
- **Alternative challenge — relative-timeout-only:** existing code already has role-local caps: 5400s fan-in/editor visibility, 900s recorder visibility/ACA timeout, 600s capture duration, navigation limits, and 3-attempt local task retry. `podcaster/video/editor.py:64-74`; `podcaster/video/job_runner.py:127-132`, `podcaster/video/job_runner.py:761-771`; `infra/modules/aca-recorder.bicep:59-69`; `podcaster/video/video_gen.py:110-215`; `podcaster/retry.py:36-130`. This **supports** lower cross-process clock complexity, but **weakens/disproves** its sufficiency for a single run-wide cutoff: independent relative limits can sum beyond the intended stage deadline and no present state ties redelivery to a prior elapsed budget.

### 2. Shared additive deadline parameters and cancellation feasibility

- **Supports:** optional keyword-only arguments can be added at the current top-level/fan-in seams without changing existing positional call forms: `run_video_generation`, `record_via_fanout`, and `wait_for_fanin`. `podcaster/video/job_runner.py:774-793`; `podcaster/video/editor.py:245-288`, `podcaster/video/editor.py:347-390`.
- **Weakens:** recorder injection uses a two-argument callable (`Callable[[VideoSegment, Path], RecordResult]`) and its unit fakes conform to that shape. `podcaster/video/recorder.py:72-75`, `podcaster/video/recorder.py:185-216`; `tests/test_recorder.py:61-75`, `tests/test_recorder.py:154-169`. Passing a required deadline argument through this seam breaks every existing recorder double unless wrapped or made optional.
- **Weakens:** inline recording’s `record_episode` does not accept a deadline and wraps `_record_segment` with generic `retry_call`; default retry is three **total attempts** with sleeps. `podcaster/video/video_gen.py:2432-2610`; `podcaster/retry.py:36-130`. A deadline parameter alone does not stop an already-entered attempt or retry sleep unless retry is budget-aware.
- **Disproves a claim of current process-tree cancellation:** composition/EDL default runners call `subprocess.run` without a timeout, while screenshot finalization has a direct-child 600s `subprocess.run` timeout. No process-group/session/kill mechanism was found in these paths. `podcaster/video/video_compose.py:1145-1165`; `podcaster/video/edl_render.py:406-414`, `podcaster/video/edl_render.py:510-548`; `podcaster/video/video_gen.py:1146-1177`. A timeout exception is not evidence that descendant ffmpeg processes are terminated.
- **Weakens browser-deadline certainty:** Playwright context/browser closure is performed in cleanup paths, but synchronous `page.goto`, `wait_for_load_state`, screenshot, or `context.close` can be blocking calls; current code has no watchdog/isolation layer. `podcaster/video/video_gen.py:1883-1939`, `podcaster/video/video_gen.py:2205-2430`, `podcaster/video/video_gen.py:2578-2610`. Cooperative deadline checks are useful but cannot be presented as hard cancellation without a separately testable process boundary.
- **Unresolved:** T+ milestones and their disposition are absent from source. No evidence defines whether an expired checkpoint should compose partially, retry, terminal-fallback, or preserve a pending state.

### 3. Terminal CAS static fallback, clip races, and media quality

- **Supports:** terminal fallback versus success manifest bytes are protected by create-if-absent CAS. The recorder rechecks a manifest after recording and conditional-writes the manifest; a late writer skips if another terminal manifest wins. `podcaster/video/recorder.py:160-182`, `podcaster/video/recorder.py:185-275`, `podcaster/video/recorder.py:279-332`; `podcaster/storage.py:307-333`. Unit tests cover manifest-present skip, mid-record winner, and no-overwrite behavior. `tests/test_recorder.py:95-111`, `tests/test_recorder.py:203-270`.
- **Weakens:** raw clip upload occurs before terminal-manifest CAS and is unconditional. A losing late recorder may overwrite the raw blob after a winning worker uploaded it but before either terminal manifest write settles; comments call it harmless based on “same bytes,” but source neither hashes nor atomically binds raw blob identity to the winning manifest. `podcaster/video/recorder.py:239-269`; `podcaster/video/clip_manifest.py:166-232`. Thus manifest immutability alone does **not** prove clip/manifest pair immutability.
- **Weakens:** fan-in regards mere manifest existence as terminal and `assemble_recording` only checks that a clip exists/downloads; it does not parse/validate `status`, clip ID/index correspondence, hash, size, codec, or probe result before assembling. `podcaster/video/editor.py:245-288`, `podcaster/video/editor.py:291-335`, `podcaster/video/editor.py:394-426`. A terminal static fallback proposal is safer only if its media integrity/decodability contract is added and tested.
- **Weakens static fallback certainty:** current production gap fill invokes `_production_record_segment`, which launches Chromium, so it is neither browser-free nor guaranteed to complete during a browser/deadline incident. `podcaster/video/editor.py:428-446`; `podcaster/video/recorder.py:443-477`. Browser-rendered generic, removed, and URL-card fallbacks also rely on context creation and finalization. `podcaster/video/video_gen.py:2090-2148`, `podcaster/video/video_gen.py:2205-2430`.
- **Supports a credible alternative but with conditions:** `render_edl` can degrade missing clips into card/intermission material and has injectable runner support. `podcaster/video/edl_render.py:406-548`; `podcaster/video/edl_render.py:45-91`. This is a potentially browser-free fallback construction seam, but it still invokes ffmpeg, defaults to a host font path, and verifies only successful exit plus output existence. `podcaster/video/edl_render.py:510-548`. It does not itself prove resulting media decodability or bundled-font availability.
- **Unresolved:** no source test proves a production static fallback is independently ffprobe-decodable, content-address-bound to its terminal manifest, or usable when Chromium and/or ffmpeg is the original failed dependency.

### 4. Checksum/probe checkpoint validation and legacy migration

- **Supports:** intermediate uploads verify byte size when the backend exposes it and delete a detected mismatched upload; download failures recompute. `podcaster/video/intermediates.py:126-218`. Recording checkpoints are already paired with a JSON sidecar and best-effort ffprobe before upload. `podcaster/video/video_gen.py:737-866`.
- **Weakens:** size verification is explicitly best-effort—an unavailable/erroring `blob_size` check passes—and checkpoint resume does not require checksum/probe metadata. `podcaster/video/intermediates.py:182-218`; `podcaster/video/video_gen.py:766-808`. The existing ffprobe is advisory and exceptions are swallowed. `podcaster/video/video_gen.py:809-838`.
- **Weakens legacy migration safety:** `IntermediateStore.read_text` returns `None` on malformed/unreadable sidecars, and existing resume code treats absent/malformed data as “re-record”; this is safe but can make a newly required sidecar cause expensive recomputation. `podcaster/video/intermediates.py:220-255`; `podcaster/video/video_gen.py:766-808`. A new strict schema would need an explicit old-checkpoint policy; otherwise durable checkpoints are silently abandoned at upgrade.
- **Weakens performance claims:** archive distribution reads the whole final MP4 into memory; adding full hash/probe passes to large artifacts can increase time and peak I/O/memory at the exact deadline boundary. `podcaster/video/distribution.py:755-799`. No source benchmark establishes that a checksum/probe transition fits a proposed remaining-budget reserve.
- **Unresolved:** no current versioned checkpoint sidecar schema covers SHA-256, source/clipset identity, stream validation, or migration; no test covers corrupt-but-size-equal binary data.

### 5. Durable `rendered_pending_distribution`, provider admission now, and deferred worker alternative

- **Supports a durable boundary as a local state record only:** main-manifest updates and publication evidence use storage `update_bytes` CAS. `_record_video_state` and `_record_video_publish` provide existing write locations, while `append_evidence` is append-only/deduplicated for publication evidence. `podcaster/video/job_runner.py:483-564`; `podcaster/publication_state.py:301-430`.
- **Weakens:** `_record_video_state` replaces the entire `generation.video_runner` mapping. Adding `rendered_pending_distribution` there without merge discipline is vulnerable to later terminal/error writes erasing the new state. `podcaster/video/job_runner.py:483-503`, `podcaster/video/job_runner.py:1375-1418`, `podcaster/video/job_runner.py:1438-1521`.
- **Weakens “provider admission now” safety:** current runner writes `upload_intent` evidence before invoking distribution, and treats a persistence failure as publication-unknown/retry-blocked. This conservatively prevents repeats but a crash after remote creation before `on_published` persists still has at-least-once risk, explicitly documented for YouTube. `podcaster/video/job_runner.py:1177-1279`; `podcaster/video/distribution.py:1020-1030`. Therefore an in-process boundary does not make provider mutation atomic.
- **Supports preservation of no-repeat/public safeguards:** `retry_is_blocked` blocks a platform when latest terminal evidence is uploaded/unknown/manual/draft/published with retry blocking. `podcaster/publication_state.py:440-467`. Distribution records YouTube initially as private/unlisted (`DRAFT_CREATED`), RSS success as pending/no external verification, and uses `on_published` snapshots. `podcaster/video/distribution.py:1036-1157`, `podcaster/video/distribution.py:1242-1351`. A deferred worker must preserve these semantics—not infer “public” from an upload response.
- **Weakens an immediate distribution-worker alternative:** queue send and manifest CAS are separate operations and the current `QueueBackend` body supports only send/receive/delete. `podcaster/queue.py:72-81`, `podcaster/queue.py:225-280`. No transactional outbox consumer, dequeue lease extension, or idempotency key/reconciliation contract for all providers exists. Moving distribution now can add an unclaimed/unconsumed outbox or duplicate provider-call window rather than remove one.
- **Supports deferral as a bounded-risk option:** keeping distribution in-process retains established canonical identity validation, pre-intent CAS, per-platform evidence/published snapshots, and current queue outcome logic. `podcaster/video/job_runner.py:1108-1418`; `podcaster/video/job_runner.py:1677-1749`. This is not proof it meets target scheduling/deadline goals, but it avoids introducing a second worker state machine before its atomicity/recovery behavior is specified.
- **Unresolved:** no `rendered_pending_distribution` state, >=1800s admission calculation, T+75/T+82/T+85 checkpoint, or distribution-worker test exists in workspace. The correct shutdown state if a deadline falls after archive but before/after provider mutation is undefined.

## Cross-cutting safeguards that a redesign must not accidentally weaken

| Material | Current evidence relationship |
| --- | --- |
| Queue poison handling | **Supports:** malformed queue bodies are deleted, schema mismatch is rejected, and clip/video transient retries stop at dequeue count 5; clip poison produces fallback. `podcaster/queue.py:117-190`; `podcaster/video/recorder.py:339-395`; `podcaster/video/job_runner.py:1685-1749`. **Weakens:** absent schema/raw JSON remains accepted for compatibility, so a schema extension cannot be assumed universally present. |
| SSRF | **Supports:** Python `safe_urlopen` fail-closes blocked/unresolvable hosts, redirects, and connect-time DNS rebinding. `podcaster/ssrf.py:109-190`, `podcaster/ssrf.py:190-391`. **Unresolved:** Playwright `page.goto` paths are not shown to use this guard. `podcaster/video/video_gen.py:1883-1939`, `podcaster/video/video_gen.py:2090-2148`. |
| Editor lease | **Supports:** lease CAS and fan-in heartbeat reduce duplicate editor work. `podcaster/video/editor.py:126-176`; `podcaster/video/job_runner.py:1032-1055`. **Weakens:** its UTC expiry is not tied to proposed budget expiration; changing fan-in polling/cutoff must retain heartbeat/release behavior or redelivery can race. |
| Queue visibility / infrastructure | **Weakens:** Bicep sets recorder replica timeout and visibility equal at 900s and editor timeout/visibility equal at 5400s. `infra/modules/aca-recorder.bicep:59-69`; `infra/modules/aca-video.bicep:68-83`. The recorder Bicep says visibility <= replica timeout, while RFC prose says visibility covers maximum record work and replica timeout is above processing budget. `docs/scaleout-recorder-rfc.md:205-220`. Existing equality does not resolve new cutoff reserve requirements. |

## Required resolving evidence / tests before treating the emerging approach as safe

1. Cross-process fake-clock tests that simulate UTC skew, delayed redelivery, and mismatch between a newly started recorder's monotonic value and an editor-projected UTC deadline.
2. A testable, process-group-aware command runner with spawned child processes proving timeout reaps the complete process tree, plus an explicit documented limitation/test for blocking Playwright calls.
3. A concurrent recorder race test where success/fallback/raw upload ordering is interleaved; assert the terminal manifest and the actual consumed binary have matching immutable identity.
4. Deterministic fallback media tests: no Playwright import/use, packaged font/assets, bounded ffmpeg, ffprobe-decodable output, and behavior when ffmpeg itself is unavailable/timed out.
5. Checkpoint migration matrix: legacy no-sidecar, malformed/unknown schema, size-equal altered bytes, bad/missing probe, hash mismatch, and recompute versus fallback disposition under remaining budget.
6. Provider-boundary crash matrix: before durable pending state, after state/before enqueue, after dequeue/before claim, after provider create/before evidence, unknown outcome, readback, and public semantic verification. An alternative worker is not sufficiently evidenced until this matrix has queue/CAS behavior and test coverage.
