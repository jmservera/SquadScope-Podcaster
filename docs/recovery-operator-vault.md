# Private recovery operator credential boundary

The two private video-recovery endpoints require both normal API authentication and a separate operator header. The old `PODCASTER_VIDEO_RECOVERY_OPERATOR_KEY` environment setting is **rejected**, including when the new settings are present. No recovery key belongs in application or workflow environment, ARM parameter files, ACA secrets, shell arguments, logs, or repository files. A fetched key necessarily exists transiently in API process memory for comparison; privileged API deployers/RG Owners are not cryptographically excluded.

## Reviewed staging (no automatic activation)

1. Review `infra/recovery-bootstrap.bicep` independently, including exact production VNet/subnet, vault name, region, networking, costs, and PE approval. Deploy this **standalone** template first: a private RBAC Standard vault, `vault` private endpoint, `privatelink.vaultcore.azure.net` DNS zone/link/group, and an **unattached** API-only identity. The template references, but never redeploys, the production VNet/subnet or ACA. Confirm FQDN resolution to the PE's private IP **from the ACA network**, not a public workstation. Do not enable public access for a failed probe.
2. The authenticated human owner must verify effective **ARM child-secret write** authority and an approved Azure control-plane secure entry with a `@secure()` input and redacted deployment history/Activity Log while public vault access is disabled. The owner alone creates a fresh independent >=256-bit `video-recovery-operator-key` via that separately controlled path; neither this repository nor its CI implements credential insertion. Stop if that route is unavailable: do not use CLI argv, agent context, env, a workflow, a source file, or a public firewall exception. Document owner-controlled operator distribution and rotation outside this repository.
3. **After** the named secret exists, independently review/deploy `infra/recovery-secret-rbac.bicep` with explicit `activation=post-owner-secret` and the bootstrap identity's principal ID. Compare that principal ID with the identity metadata before deployment. The only grant is `Key Vault Secrets User` at the *named secret resource*; it includes secret get and metadata read and covers future versions. Confirm its effective scope and propagation without retrieving plaintext. Never grant the shared synthesis identity, worker, UI, or vault/RG-wide access.
4. Configure protected `prod` variables `PODCASTER_VIDEO_RECOVERY_STATE=inactive` and `PODCASTER_VIDEO_RECOVERY_EXPECTED_LIVE_STATE=inactive` before merging a workflow change. An active transition requires separate reviewed authorization `PODCASTER_VIDEO_RECOVERY_TRANSITION_APPROVED=true`, three exact image digests, a reviewed full-stack baseline with `deploy_vnet=true` on an existing private VNet, a redacted exact-production ARM validate/what-if, and resolution of the independent #780 ACR **target** manifest/config/provenance readback STOP. Never substitute a sandbox digest, recreate/delete the VNet, or run the old deployment default with `deploy_vnet=false`. After an approved transition, update the protected expected-live state only after API identity/env and revision-health metadata are verified; mismatches stop later deployments. Deactivation is also a separately approved pinned-image transition.

In active state only the API has the dedicated identity plus non-secret `PODCASTER_VIDEO_RECOVERY_OPERATOR_SECRET_URI` (derived, versionless, named-secret URI) and `PODCASTER_VIDEO_RECOVERY_IDENTITY_CLIENT_ID`. Its pre-existing shared identity/`AZURE_CLIENT_ID`, API key, registry, secrets, and worker/UI configuration remain unchanged. The application uses that dedicated identity to fetch the latest enabled version, checks not-before/expiry, and caches a single key up to 60 seconds (or earlier expiry). A failed refresh clears the key; no stale/older version or API-key fallback. Outages can go unnoticed until a fresh cache expires; immediate revocation is **not** guaranteed. Reconciliation checks the same boundary before touching storage or queue.

Rotate by owner-created new version, private non-disclosing verification, and waiting for max cache TTL plus propagation margin before retiring old operator distribution. For compromise, protectively disable the API recovery revision/reconciler, then rotate/revoke and remove RBAC as appropriate; do not rely on the TTL for emergency containment. No recovery endpoint or public provider call is part of vault staging. Private PE/DNS have ongoing charges (roughly $7.80/730-hour month retail fixed plus traffic, DNS, Key Vault operations and logging); confirm subscription pricing before creation. Purge protection and PE/DNS charges persist after a failed bootstrap.
